01 변수와 타입

val은 재할당 불가(불변), var는 재할당 가능. 기본은 항상 val부터 시작합니다.

val name = "Kotlin"      // 불변 — 타입은 String으로 추론됨
var count = 0             // 가변
count = 1                  // OK
// name = "Java"          // 컴파일 에러

val age: Int = 30          // 타입 명시도 가능
val height: Double = 175.5
val isStudent: Boolean = true
val initial: Char = 'K'

// 문자열 템플릿 — Java의 + 연결 대신 $ 사용
println("이름: $name, 내년 나이는 ${age + 1}살")
알아두기 Kotlin의 Int, Double, Boolean 등은 전부 객체이며 Java 같은 primitive/wrapper 구분이 없습니다. 컴파일러가 가능한 경우 알아서 primitive로 최적화합니다.

02 함수

단일 표현식 함수, 기본값 파라미터, 이름 있는 인자가 Kotlin 함수의 핵심 특징입니다.

fun add(a: Int, b: Int): Int {
    return a + b
}

// 단일 표현식 함수 — 중괄호/return 생략
fun square(x: Int): Int = x * x

// 반환 타입도 추론 가능
fun greet(name: String) = "Hello, $name!"

// 기본값 파라미터
fun power(base: Int, exp: Int = 2) = Math.pow(base.toDouble(), exp.toDouble())

power(3)                       // exp는 기본값 2 사용
power(base = 2, exp = 10)       // 이름 있는 인자 — 순서 무관
power(exp = 3, base = 2)        // 순서 바꿔도 OK

파라미터 개수가 많아지면 세로로 나열하는 게 관례입니다 (trailing comma 포함):

fun createPerson(
    name: String,
    sessionId: Int = 0,
    connected: Boolean = false,
    role: String = "guest",
) { /* ... */ }

03 제어문

Kotlin에서는 if와 when이 값을 반환하는 표현식으로도 쓰입니다.

// if 표현식 — 삼항연산자 대체
val max = if (a > b) a else b

// when — switch보다 강력함 (범위, 타입, 임의 조건 사용 가능)
val description = when {
    age < 13 -> "어린이"
    age < 20 -> "청소년"
    else -> "성인"
}

val typeName = when (value) {
    is Int -> "정수"
    is String -> "문자열"
    else -> "기타"
}

// for — 범위(range) 기반
for (i in 1..5) println(i)          // 1,2,3,4,5
for (i in 5 downTo 1 step 2) { }     // 5,3,1
for (i in 0 until 5) { }             // 0,1,2,3,4 (5 미포함)

// while은 Java와 동일
var i = 0
while (i < 5) { i++ }

04 Null 안전성

Kotlin 타입 시스템은 "null이 될 수 있는지"를 타입에 포함시켜 NPE를 컴파일 타임에 막습니다.

var nickname: String? = null    // '?' 가 있어야 null 허용

// nickname.length              // 컴파일 에러 — null일 수 있어서 바로 접근 불가

val len = nickname?.length              // 안전 호출 — null이면 결과도 null (Int?)
val len2 = nickname?.length ?: 0         // 엘비스 연산자 — null이면 기본값 0 (Int)
val len3 = nickname!!.length             // non-null 단언 — null이면 NPE 발생 (주의해서 사용)

nickname?.let {
    println("별명: $it")   // nickname이 null이 아닐 때만 실행
}
!! 사용 주의 !!는 "null 아님을 확신한다"는 선언이라 틀리면 그대로 NPE가 납니다. 가능하면 ?:나 ?.let으로 처리하는 걸 권장합니다.

05 클래스와 데이터 클래스

주 생성자에 val/var를 붙이면 파라미터 선언과 프로퍼티 선언이 한 번에 끝납니다.

class Person(
    val name: String,
    var sessionId: Int = 0,
    var connected: Boolean = false,
)

val p = Person("Kim")
val p2 = Person("Lee", sessionId = 5, connected = true)
p2.sessionId = 10        // var라서 재할당 가능
println(p.name)           // getter 없이 프로퍼티처럼 접근

data class — DTO/모델에 최적

data class Person(val name: String, var sessionId: Int = 0)

val a = Person("Kim", 1)
val b = Person("Kim", 1)

a == b                 // true — 필드값 기준 비교 (equals/hashCode 자동 생성)
println(a)               // Person(name=Kim, sessionId=1) — toString 자동 생성
val c = a.copy(sessionId = 2)   // 일부 필드만 바꾼 복사본

커스텀 getter/setter

생성자 괄호 안에서는 커스텀 접근자를 못 붙입니다. 검증/로깅이 필요한 프로퍼티만 본문으로 옮기세요.

class Person(
    val name: String,
    sessionId: Int = 0,      // val/var 없음 — 초기화 값 전달용 파라미터
) {
    var sessionId: Int = sessionId
        set(value) {
            field = value.coerceAtLeast(0)   // field: 실제 저장공간(backing field)
        }

    var lastLoginAt: Long = 0
        private set           // 밖에서는 읽기만 가능
}
field 키워드 커스텀 setter 안에서 프로퍼티 이름을 그대로 쓰면(sessionId = value) 무한 재귀에 빠집니다. 반드시 field로 backing field에 접근해야 합니다.

보조 생성자 (secondary constructor)

대부분의 경우 기본값 파라미터로 충분하지만, 다른 방식의 초기화가 필요하면 constructor로 추가할 수 있습니다. 항상 주 생성자를 거쳐야(this(...)) 합니다.

class Person(val name: String, var sessionId: Int = 0) {
    constructor(name: String) : this(name, sessionId = 0) {
        println("$name 새 세션 시작")
    }
}

06 컬렉션

List(순서 있는 목록), Set(중복 없는 집합), Map(key-value)이 3대 컬렉션입니다. 기본은 읽기 전용, mutable 접두 버전이 변경 가능 버전입니다.

List

val names = listOf("Kim", "Lee")
names[0]              // "Kim"
names.size

val m = mutableListOf("Kim")
m.add("Lee")
m.removeAt(0)

Set

val ids = setOf(1, 2, 2, 3)   // {1,2,3}

val m = mutableSetOf<Int>()
m.add(1)
m.contains(1)   // true

Map

val sessions: Map<String, Int> = mapOf("Kim" to 101, "Lee" to 102)
sessions["Kim"]        // 101 (타입은 Int?)
sessions["Choi"]        // null

val mutableSessions = mutableMapOf<String, Int>()
mutableSessions["Kim"] = 101   // 삽입/갱신
mutableSessions.remove("Kim")

for ((name, id) in sessions) {
    println("$name -> $id")
}

"Kim" to 101은 Pair("Kim", 101)을 만드는 중위 함수 호출입니다.

07 람다와 고차함수

컬렉션은 for문보다 람다를 인자로 받는 함수와 함께 쓸 때 진가를 발휘합니다.

data class Person(val name: String, var connected: Boolean = false)

val people = listOf(
    Person("Kim", true),
    Person("Lee", false),
    Person("Park", true),
)

people.filter { it.connected }          // 조건에 맞는 것만 → [Kim, Park]
people.map { it.name }                    // 각 요소 변환 → [Kim, Lee, Park]
people.forEach { println(it.name) }       // 순회
people.find { it.name == "Kim" }          // 첫 매칭 (없으면 null)
people.any { it.connected }               // 하나라도 있으면 true
people.all { it.connected }               // 전부 만족해야 true
people.count { it.connected }             // 개수

// 체이닝 — 실무에서 가장 흔한 패턴
val onlineNames = people
    .filter { it.connected }
    .map { it.name }
    .sorted()

it은 람다가 파라미터 하나만 가질 때 쓸 수 있는 암묵적 이름입니다. 명시하려면 { person -> person.connected }처럼 씁니다.

08 확장 함수

기존 클래스(내가 만들지 않은 클래스 포함)에 새 함수를 "추가"할 수 있습니다. 상속이나 래퍼 클래스 없이 가독성 좋은 API를 만드는 Kotlin 특유의 기능입니다.

// String에 함수 하나를 추가
fun String.isValidSessionId(): Boolean = this.isNotBlank() && this.length >= 4

"abcd".isValidSessionId()     // true — 마치 String의 원래 메서드처럼 호출

// 우리가 만든 클래스에도 적용
data class Person(val name: String, var connected: Boolean = false)

fun Person.displayLabel(): String =
    if (connected) "$name (온라인)" else "$name (오프라인)"

val p = Person("Kim", true)
println(p.displayLabel())      // "Kim (온라인)"
내부 동작 실제로 클래스를 수정하는 게 아니라, 컴파일 시점에 displayLabel(person) 같은 정적 함수 호출로 변환됩니다. 그래서 private 멤버에는 접근할 수 없습니다.

09 스코프 함수 (let / run / with / apply / also)

객체를 받아 블록을 실행하고, 그 결과나 객체 자신을 돌려주는 함수들입니다. 처음엔 헷갈리지만 실무 Kotlin 코드에서 매우 자주 보입니다.

함수블록 안 참조반환값주 용도
letit블록의 결과null 체크 후 처리, 값 변환
runthis블록의 결과객체 초기화 + 계산 결과 반환
withthis블록의 결과한 객체의 멤버를 여러 번 다룰 때
applythis객체 자신객체 설정(빌더 패턴처럼)
alsoit객체 자신로깅 등 부수 작업 끼워넣기
 
val person = Person("Kim").apply {
    connected = true          // this 생략 — 프로퍼티 바로 접근
}   // person 자신을 반환

val label = person.let {
    if (it.connected) "온라인" else "오프라인"
}   // let의 블록 결과(String)를 반환

person.also {
    println("생성됨: ${it.name}")   // 로깅만 하고 person 자신을 그대로 반환
}.connect()

10 예외 처리

문법은 Java와 비슷하지만, Kotlin에는 checked exception이 없습니다 — throws 선언이 강제되지 않습니다.

fun parseSessionId(raw: String): Int {
    return try {
        raw.toInt()
    } catch (e: NumberFormatException) {
        println("잘못된 sessionId: $raw")
        -1
    } finally {
        println("파싱 시도 종료")
    }
}

// try도 표현식이라 값으로 바로 받을 수 있음
val id = parseSessionId("abc")   // -1

// 커스텀 예외
class InvalidSessionException(message: String) : Exception(message)

fun requireConnected(person: Person) {
    if (!person.connected) {
        throw InvalidSessionException("${person.name} is not connected")
    }
}

11 enum과 sealed class

상태나 종류가 정해진 값을 표현할 때 씁니다. when과 함께 쓰면 분기 누락을 컴파일러가 잡아줍니다.

enum class ConnectionState { CONNECTING, CONNECTED, DISCONNECTED }

fun describe(state: ConnectionState) = when (state) {
    ConnectionState.CONNECTING -> "연결 중"
    ConnectionState.CONNECTED -> "연결됨"
    ConnectionState.DISCONNECTED -> "끊김"
    // 하나라도 빠뜨리면 컴파일 에러 (when이 exhaustive해야 함)
}

// sealed class — enum보다 유연함 (각 케이스가 데이터를 가질 수 있음)
sealed class NetworkResult
data class Success(val data: String) : NetworkResult()
data class Failure(val error: Throwable) : NetworkResult()
object Loading : NetworkResult()

fun handle(result: NetworkResult) = when (result) {
    is Success -> println("받음: ${result.data}")
    is Failure -> println("실패: ${result.error.message}")
    Loading -> println("로딩 중")
}
